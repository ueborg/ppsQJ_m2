# Task directory template

Copy this whole directory to `research/tasks/active/<TASK-ID>/` when a
`/research` run opens. `TASK-ID` is `TASK-YYYY-MM-DD-<SHORTNAME>`.

**Nothing in a task directory is authoritative.** This is the execution plane:
cheap, disposable, and never citable as support. Only `research/state/**` is
canonical, and only the researcher writes it.

## Layout

**Start by initialising the phase ledger** — it is not copied with the
template, it is generated:

```bash
.venv/bin/python3 research/tools/task_phase.py \
    research/tasks/active/<TASK-ID> init <TASK-ID> --mode normal
```

Two files are deliberately **not** in the template, because their presence
means something: `TASK_MANIFEST.yaml` (generated by `init`) and
`COLLABORATION_LOG.yaml` (copied from `research/templates/` only when a
collaboration round is actually opened). A log sitting in a task that never
collaborated is validator error `C1`.

| `SOURCE_REGISTER.md` | `research/SOURCE_REGISTER.md`, task-scoped | Stage 0 |
| `FIELD_MAP.md` | `research/FIELD_MAP.md` | Stage 2 |

| `FALSIFICATION_RESULTS.md` | outcomes, append-only, written after the plan froze | Stage 4 |

`EXPERIMENT_SPEC.yaml` appears in `proposed/` only if a candidate survives.
It is a **proposal**; it becomes an authorisation token only when the researcher
approves it into `research/experiments/<EXP-ID>.yaml` — and that token
authorises **preparation**, never submission. **No agent ever submits an HPC
job.** An HPC-bound package terminates at `READY_FOR_HUMAN_SUBMISSION` and the
researcher submits it manually. See `research/RESOURCE_POLICY.md` §4.

## Rules

- Artifacts keep the charter's mandated filenames wherever practical, so a
  reader who knows the charter can navigate a task directory without this file.
- `agent_reports/` holds raw worker output. **Do not edit it into agreement.**
  Preserved disagreement is the point (charter §4.4).
- `REDTEAM.yaml` must pass
  `.venv/bin/python3 research/tools/validate_redteam.py <path>`, and must use
  **schema v2**: one review, with its own nine attacks and its own verdict, per
  candidate. A fatal attack kills the candidate it applies to and cannot erase
  an unrelated survivor.
- **Phases close through the ledger, never by hand:**
  `task_phase.py <TASK_DIR> close <stage>`. Closing freezes that stage's
  artifacts by SHA-256; editing one afterwards is validator error `M5`. A
  legitimate correction is recorded with `task_phase.py ... amend`.
- **The pre-specified plan and its results are different files.** Never merge
  `FALSIFICATION_RESULTS.md` back into `FALSIFICATION_PLAN.md`.
- **First passes are independent, then frozen.** The three investigators must
  not see each other's conclusions while writing. `close first_pass_frozen`
  hashes every file in `agent_reports/`; it refuses to close if a dispatched
  worker produced no report.
- **Collaboration is optional and happens at most once.**
  `task_phase.py <TASK_DIR> collaborate open --dependency … --roles … --question
  … --value …` must justify the round before it opens; `collaborate none
  --reason …` records `COLLABORATION_NOT_NEEDED`. The red team is never a
  participant. Messages are atomic — never forward a peer's report.
- **Collaboration never rewrites a first-pass report.** A changed conclusion is
  recorded in `COLLABORATION_LOG.yaml` as `FIRST_PASS` /
  `AFTER_CROSS_EXAMINATION` / `WHY_CHANGED`. Preserved disagreement is a valid
  output.
- The whole directory must pass
  `.venv/bin/python3 research/tools/validate_task.py <path>`.
- On completion the directory moves to `research/tasks/completed/` or
  `research/tasks/killed/`. **It is never deleted** — a killed direction is a
  preserved negative result.
