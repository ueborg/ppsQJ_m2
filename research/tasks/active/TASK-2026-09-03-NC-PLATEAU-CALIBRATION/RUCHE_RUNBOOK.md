# RUCHE_RUNBOOK — the exact commands, for the researcher to type

**No agent runs any of this.** `research/RESOURCE_POLICY.md` §4 forbids agent
submission unconditionally — not "until a gate", not "once approved", not "when
HPC access returns". Nothing in this package contains an executable scheduler
call, and every arm's preflight asserts that about itself before it will pass.

**17 immediate arrays · 3 280 tasks · ~2 180 core-hours (3 052 pessimistic) ·
~31 h elapsed for the long pole, excluding queue wait.**

Replace `<user>`, `<host>` and `$WORKDIR` for your account.

## 3. Check your queue accounting BEFORE relying on any elapsed figure

The cost model assumes `%64` grants 64 concurrent slots **per array**.

```bash
sacctmgr show assoc where user=$USER format=Account,Partition,GrpTRES,MaxJobs,QOS
sacctmgr show qos format=Name,MaxJobsPU,MaxSubmitPU,MaxTRESPU
```

- Granted **per array** → leave `%64` alone.
- Granted as a **shared total** → lower `%64` on the `cpu_med` arms, and submit
  largest-per-task first (§5 order). **The `%N` cap is the only number in these
  scripts that is safe to hand-edit**; everything else is regenerated by
  `tools/build_arms.py` and the preflight fails if you touch it.
- If `cpu_long` turns out to be QOS-limited for this account, **stop and report
  it**. Do not fall back to `cpu_short`: it is effectively serialised for this
  account (`MOCK-LOWLAMBDA-EXTENSION/SCHEDULER_DECISION.md`) and the campaign's
  parallelism assumption would then be wrong programme-wide, which is worth
  knowing rather than working around.

## 4. Preflight — every immediate arm must exit 0

```bash
cd $WORKDIR/ppsQJ_m2/research/tasks/active/TASK-2026-09-03-NC-PLATEAU-CALIBRATION

for arm in A_L64_nc2048_topup A_L64_nc4096 A_L64_nc8192 \
           B_L64_cross_nc512 B_L64_cross_nc1024 B_L64_cross_nc2048 \
           B2_L32_nc512 B2_L32_nc1024 B2_L32_nc2048 \
           B2_L48_nc512 B2_L48_nc1024 B2_L48_nc2048 \
           C_L96_nc1024 C_L96_nc2048 D_L128_nc2048 \
           E_L64_dtau_nc64 E_L64_dtau_nc256 ; do
    ( cd $arm && PYTHON=$PPSQJ_PYTHON ./run_preflight.sh >/dev/null ) \
        && echo "PASS  $arm" || echo "FAIL  $arm"
done
```

All seventeen must print `PASS`. Then read one in full and check:

- `PREFLIGHT PASSED` at the end;
- `manifest == frozen design` — this is the check that matters most;
- `bundled instrumented.py  sha256 0a33c4034cda70ea…  (matches manifest)`;
- `SUCCESS_CRITERIA.yaml  sha256 …` and `ANALYSIS_SPEC.yaml  sha256 …` — if
  either differs from `VALIDATION.md`, a frozen spec was edited. **Stop.**
- `--partition`, `--time`, `--mem` all `OK`;
- `results already present: 0 / N` on a first run.

The conditional arms will print `BLOCKED` and exit 3. **That is correct** and
they are deliberately absent from the loop above.

## 7. Check failures, and settle the memory question while you are there

```bash
# any task that wrote to stderr
grep -l . */logs/*.err 2>/dev/null | head -40

# out-of-memory and timeout are the two failure modes this campaign can hit
sacct -u $USER --starttime=today \
      --format=JobID%20,JobName%18,State,ExitCode,Elapsed,ReqMem,MaxRSS%10 \
    | grep -E 'OUT_OF_ME|TIMEOUT|FAILED'
```

`[!]` **Please run this one and send it back.** It is the first `MaxRSS`
measurement of this sampler on the cluster that will exist anywhere:

```bash
sacct -j <the D_L128_nc2048 job id> --format=JobID%20,MaxRSS,MaxVMSize,Elapsed
```

`COST_MODEL.md` §4 records that the `--mem` model every predecessor package used
was never checked against a running process, and that direct local measurement
shows it under-predicts. `D_L128_nc2048` is the largest **modelled** (rather than
measured) memory request in the campaign at 14G against a modelled 9.9 GB. One
`sacct` line settles it for the whole programme.

## 8. Completeness

```bash
for arm in A_L64_nc2048_topup:24 A_L64_nc4096:48 A_L64_nc8192:48 \
           B_L64_cross_nc512:336 B_L64_cross_nc1024:264 B_L64_cross_nc2048:336 \
           B2_L32_nc512:336 B2_L32_nc1024:264 B2_L32_nc2048:336 \
           B2_L48_nc512:336 B2_L48_nc1024:264 B2_L48_nc2048:336 \
           C_L96_nc1024:24 C_L96_nc2048:24 D_L128_nc2048:16 \
           E_L64_dtau_nc64:144 E_L64_dtau_nc256:144 ; do
    a=${arm%%:*}; n=${arm##*:}
    got=$(find $a/results -maxdepth 1 -name '*.json' | wc -l | tr -d ' ')
    printf '%-24s %4s / %s%s\n' "$a" "$got" "$n" \
           "$([ "$got" = "$n" ] || echo '   <-- INCOMPLETE')"
done
```

3 280 total. **Re-submitting an array is safe and idempotent**: `run_cell.py`
skips any row whose output JSON already exists, so a partial array is topped up
rather than recomputed.

## 10. The analysis — one command, and it is the only place the criteria live

```bash
cd /Users/catlover1337/Documents/ppsQJ_m2
.venv/bin/python3 \
  research/tasks/active/TASK-2026-09-03-NC-PLATEAU-CALIBRATION/analysis/nc_plateau_analysis.py \
  | tee research/tasks/active/TASK-2026-09-03-NC-PLATEAU-CALIBRATION/NC_PLATEAU_ANALYSIS.txt
```

It writes `NC_PLATEAU_RESULTS.json` and figures A–L under `analysis/figures/`,
and prints, in order: the two budgets (`N_c` and `R`) per cell; campaign A's
P1–P5 and asymptotic-form verdict; campaign B's seven-point curves with the full
quality battery and H1/H2/H3; the locator convergence, matched and one-sided;
`L = 96` and `L = 128`; and campaign E's E1/E2 verdict at each `N_c`.

It runs to completion with zero, partial or complete results and says which.

**Then, and only then**, write `FALSIFICATION_RESULTS.md` against the **frozen**
`FALSIFICATION_PLAN.md`, and walk `DECISION_TREE.md` from its entry condition.
The plan is frozen and the results are a different file. Do not edit the plan to
match what happened.

## 11. If a branch says "not ready"

Report it. `FALSIFICATION_PLAN.md` Y8 pre-registers six negative outcomes,
including the most likely one — `UNRESOLVED_R_LIMITED` at `L = 96` and
`L = 128` — so reporting them is not a retreat. **No arm is re-run
automatically.** Any extension needs a fresh task, a fresh justification that is
not "the last one did not work", and a human gate.
